# 应急响应

当出现链上或链下异常时，建议按以下顺序处理。

## 1. 先分类

- 合约逻辑异常
- 前端展示异常
- API 异常
- indexer 落后或卡住
- 数据库异常
- RPC 不可用

## 2. 基础检查

- `GET /healthz` 是否正常
- indexer 是否还在推进 checkpoint
- MySQL 是否可连通
- RPC 是否可访问
- 当前链配置是否仍指向正确合约

## 3. 临时处置

- 前端异常时先切换到只读查询
- indexer 异常时优先恢复同步，不先改业务代码
- 配置异常时先修正环境文件，再重启进程
- 如怀疑合约缺陷，停止继续引导用户发新交易

## 4. 事后记录

每次事故建议记录：

- 时间
- 影响范围
- 触发原因
- 处置动作
- 恢复时间
- 后续修复项
