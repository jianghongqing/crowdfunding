# 开发协作规则

## 优先级

1. 先遵守 `AGENTS.md`
2. 再按 `CLAUDE.md` 和 `.claude/context.md` 建立上下文
3. 最后才展开具体模块文件

## 改动原则

- 小步修改，避免无关重构
- 保持“合约 / API / indexer / 前端”分层不混乱
- 不随意改用户可能正在维护的前端文件
- 不改 ABI 绑定，除非合约 ABI 真变了

## 安全原则

- 不提交真实私钥、RPC Key、数据库密码
- 不提交真实生产链配置
- 不扩大本地工具权限后再提交配置文件
- 不把临时产物、可执行文件、编号备份文件提交进仓库

## 联动检查

- 改数据库结构：检查 `backend/migrations/`
- 改部署行为：检查 `docs/DEPLOYMENT.md` 和 `docker-compose.yml`
- 改查询结构：检查前端调用是否兼容
- 改合约事件：检查 indexer 和 store 是否同步更新

## 提交前最小自查

- 是否改到了不该动的生成文件
- 是否需要补 migration
- 是否需要补文档
- 是否引入了新的权限点或安全边界变化
